## 这份任务书怎么来的

不是拍脑袋列的。做法是：

1. 拉取全部 51 个 Issue，提取每个的**输出物**与**验收标准**；
2. 按 `[LabN]` 前缀分到 8 个 Lab；
3. 逐条到仓库里找对应文件，判断「有 / 不全 / 没有」。

**一个必须说明的发现**：部分 Issue 的「输出物」字段与标题对不上，是建 Issue 时复制模板错位造成的。例如：

| Issue | 标题说的是 | 输出物字段写的是 |
| --- | --- | --- |
| #44 | 归档看板截图 | Review 演示录屏、`docs/retro/sprint-3.md` |
| #41 | 编写 ADR-002 Maven 多模块 | `docs/lab1/board-screenshot.png` |
| #42 | 配置 ESLint / Prettier / Husky | `docs/adr/ADR-002-package-structure.md` |
| #43 | Sprint 3 Review + Retro | pnpm lint / typecheck 全绿 |

所以对照时**以标题为准**，「输出物」字段只作参考。这一条本身就值得记一笔：模板复制后没有逐条核对，是流程上的疏漏。

# 三条不能碰的红线

1. **会议纪要不能编。** 没开过的会，就写「未召开，决议通过 PR 异步完成」。编一份假纪要，被问一句「这会谁主持的」就穿帮。
2. **访谈记录不能编。** 同理。时间不够就删掉用户画像里那两个字段，删掉比编造干净。
3. **部署不能说「已上线」。** 只能说到「链路就绪，无真机验证」。这件事已经在 #101 里如实留账，不要在其他地方改口。
