## 使用方式

1. **开发前**：实现某个方法前先读对应 Scenario，明确边界与错误码，不要只看主路径。
2. **开发后**：Scenario 即验收清单，逐条核对；`co-qa-domain` 的单元测试与这些场景一一对应。
3. **契约变更**：先改 `.feature` 再改代码，两者不一致时以 `.feature` + 领域测试为准并同步 PR 说明。

## 约定

- 关键字统一 `# language: zh-CN`，用 `功能 / 背景 / 场景 / 假设 / 当 / 那么 / 并且`；
- 只写**可观测行为**（状态码、错误码、状态变化），不写实现细节（类名、方法名）；
- 未在 `docs/错误码.md` 登记的错误码不写死，只写 HTTP 语义，等实现时补码；
- 新增故事时同步更新本索引与 `docs/02-需求/Product-Backlog.md` 的验收标准列。
