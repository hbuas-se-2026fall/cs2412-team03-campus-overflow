# 用户画像

>
> **口径说明（2026-11-12）**：本文件四张画像均为**基于角色推断的原型，而非访谈结论**。已完成的真实调研汇总见 [docs/product/user-interviews.md](../product/user-interviews.md)（10 份样本：在校生 5、往届学长 4、年级辅导员 1，含原话节选与按题统计）；该轮调研**未覆盖「平台管理员」**，所以画像四的痛点与引语不做补写，避免凭空编造。后续若补访管理员，按 [访谈纪要模板](用户访谈/访谈纪要-模板.md) 归档后再回填。

## 画像一：学生 ·「林小问」

- 身份：大二，数据结构与算法课程在读
- 典型场景：晚上刷题遇到红黑树插入失衡，翻书没搞懂，班级群问了没人回，第二天上课还没解决。
- 核心诉求：能按课程和标签快速提问、收到解答通知、问题以后能被搜到。
- 痛点：公开社区答案与本校教材/进度对不上；班级群消息刷走，问题无人跟进。
- 一句话引语："我就想知道，这个知识点我们课上到底怎么讲的。"

## 画像二：助教 / 研究生 ·「陈助教」

- 身份：研一，担任数据结构课程助教
- 典型场景：每周要给几十个学生答疑，重复问题答过很多遍，希望优质回答被沉淀、自己能背书。
- 核心诉求：浏览待回答问题、背书一次优质回答、管理课程标签、看谁贡献大。
- 痛点：重复劳动；无法区分认真回答的人和灌水的人。
- 一句话引语："这个问题上周刚答过，能不能让它自己浮出来。"

## 画像三：教师 ·「王老师」

- 身份：课程主讲教师
- 典型场景：开学创建课程、拉学生进班，课后关注哪些问题被卡住了。
- 核心诉求：创建课程、审批成员、查看答疑概况（不逐条回答）。
- 痛点：缺少课程内问题分布的直观反馈。
- 一句话引语："我想知道全班到底卡在哪一章。"

## 画像四（管理员）：平台治理 ·「管理员」

- 身份：课程实验平台管理员
- 典型场景：处理违规内容、维护平台稳定。
- 核心诉求：删除违规帖子、查看系统健康。
- 痛点与引语：**未访谈，暂缺**（见顶部口径说明）。当前只列职责与典型场景，不虚构原话。
