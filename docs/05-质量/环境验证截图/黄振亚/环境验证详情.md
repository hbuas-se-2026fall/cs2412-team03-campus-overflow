### 执行命令（2026-11-01 12:15 起，仓库 `hbuas-se-2026fall/cs2412-team03-campus-overflow` @ `4e847d0`）

```bash
git --version && java -version && mvn -v && node -v && npm -v
cd backend
mvn -B -DskipTests compile
mvn -B -Dmaven.test.failure.ignore=true test
cd ../frontend
npm install --no-audit --no-fund
npm run typecheck
npm run build
npm run dev
```

> ⚠️ **不要用 `-fae` 统计失败数**。`-fae`（fail at end）虽然会继续构建，但失败模块的下游会被
> `SKIPPED`，实测只能数到 34 个失败，会误判成"少了 4 个"。
> `-Dmaven.test.failure.ignore=true` 才能跑完全部模块并拿到真实值。

### 给团队的建议

1. **基线数字该更新了。** 38 是 S0 骨架口径，Q&A 领域层转绿后真实基线是 23。建议把
   `环境验证记录.md` 的「基线说明」改成"随 `#9` 合并后为 23"，否则后面每个同学都会被判"少统计"。
2. **统计失败数务必用 surefire 报告口径**，不要数日志里 `[ERROR]` 行——日志行数会重复计。
   本次以 `backend/**/target/surefire-reports/TEST-*.xml` 汇总为准，得出 54/3/20/23。
3. **后端启动验证需要 Docker**，本机没装所以那一栏是"未验证"。建议 SM 在有 Docker 的环境补一次
   `docker compose -f deploy/docker-compose.yml up -d mysql redis` 的验证，或把这一项明确标为"全员待补"。
4. **前端首页会显示"请求失败"**，因为 `/api/questions` 代理到 `localhost:8080` 而后端没起。
   这是预期现象，不是前端缺陷，评图时别误判。
