## 四、怎么复现

```bash
# 全后端测试 + 覆盖率报告（每个有测试的模块生成 target/site/jacoco/jacoco.csv）
cd backend
mvn -o -B -ntp test
mvn -o -B -ntp jacoco:report

# 门禁（正向通过 / 反向必须红）
mvn -o -B -ntp verify -DskipITs -pl '!co-bootstrap'
mvn -o -B -ntp verify -DskipITs -pl '!co-bootstrap' -Ddomain.coverage.minimum=0.999

# 前端
cd frontend && npm test
```

汇总口径：`LINE_COVERED / (LINE_COVERED + LINE_MISSED)`，分支用 `BRANCH_COVERED / (BRANCH_COVERED + BRANCH_MISSED)`。

## 五、与门禁的关系

- 门禁按模块分级（全局 0.75，有测试的模块 0.90~0.95），只看**行覆盖率**，不看分支；
- 门禁对**没有 `jacoco.exec` 的模块静默跳过**，所以第三节那些「0 个用例」的模块在门禁上是**绿的**——
  这正是需要这张表的原因；
- CI 阶段 2b 有 `jacoco.exec` 存在性断言，能发现「该生成却没生成」，但发现不了「模块本来就没有测试」；
- 2026-11-16 起门禁的定位写清楚了：**防回退，不是 KPI**。所有阈值都取「实测 − 3~10 个点」，
  没有一个是「希望达到的目标值」——那种写法会在第一次正常重构时把人逼着改门禁，最终门禁就废了。
