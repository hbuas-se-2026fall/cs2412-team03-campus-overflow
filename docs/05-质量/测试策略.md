# 测试策略

> 测试金字塔：上层少而慢，下层多而快。本项目以领域单元测试为重心。

| 层级 | 工具 | 覆盖对象 | 运行命令 | 目标 |
| --- | --- | --- | --- | --- |
| 单元测试 | JUnit 5 + Mockito | 领域聚合、值对象 | `mvn test -pl <module>` | 领域覆盖率 ≥70%，核心聚合 ≥90% |
| 应用层测试 | JUnit 5 + 假实现 | 用例编排、事件发布 | `mvn test -pl co-qa/co-qa-application` | 关键用例全覆盖 |
| 集成测试 | Testcontainers + MySQL/Redis | Controller→Service→Repository | `mvn verify` | 端到端链路通过 |
| 契约测试 | OpenAPI 校验（可选 Pact） | 前后端接口 | `npm run typecheck` + 手工核对 | S2 起每个接口有契约 |
| 端到端 | Playwright（S4 可选） | 关键用户旅程 | `npx playwright test` | 3 条主链路 |
| 架构测试 | ArchUnit | 分层与依赖 | `mvn test -pl co-bootstrap -Dtest=ArchitectureTest` | 全过 |

## 原则

1. 红-绿-重构：先看测试规格（`src/test`），再实现；
2. 不改已有测试断言；新功能必须补测试；
3. 领域层不依赖框架，测试不启 Spring 上下文；
4. 异步声誉结算用幂等消费，对账测试覆盖冻结-扣减-退还守恒；
5. 覆盖率门禁已在 S4 升级为**全模块生效**（不再是「只卡 Q&A 一个模块」），任何模块掉到 0.70 以下即红；
   `skeleton-check` 仍然必须绿——它是骨架期的遗留护栏，与覆盖率门禁并行，不互相替代。

## 覆盖率口径与门禁现状

门禁只有一处定义，在 `backend/pom.xml` 的 JaCoCo 执行 `check-all-modules` 里（Issue #97 起从 CI 命令行搬回根 POM）：

| 项 | 值 | 说明 |
| --- | --- | --- |
| 规则 | `BUNDLE` / `LINE` / `COVEREDRATIO` | 行覆盖率，不是分支覆盖率 |
| 阈值 | `domain.coverage.minimum = 0.70` | 只在根 POM 定义一次 |
| 生效范围 | 27 个 Maven 模块全部继承 | 父 POM 的 `<plugins>` 会被所有模块继承 |
| 失败行为 | `haltOnFailure=true` | 低于 0.70 直接构建失败，不会只警告 |
| 逃生舱 | `jacoco.check.skip` | 只能在模块自己的 POM 覆写，且必须写清原因与解除条件；**不许用命令行 `-D` 或调低阈值绕过** |

没有生成 `jacoco.exec` 的模块 JaCoCo 会静默跳过，这个风险由 CI 阶段 2b 的 exec 存在性断言守住，
所以「门禁绿」不等于「每个模块都真有测试」——这两件事分开验证。

**当前实测（本地 `mvn test` 全绿后汇总）**：全后端行覆盖率 **79.1%（1495 / 1891）**，高于门禁 8.1 个百分点；
其中 `co-reputation-application` 47 个测试、248 行代码覆盖 246 行 = **99.2%**，是全仓最高的一块。
复现命令：`cd backend && mvn verify -DskipITs`。

> 口径提醒：网上流传的 74.3%（答辩 PDF）与 76.0%（PR #102 描述）都是更早的快照，
> 与当前代码不一致，引用时以本节数字为准。
>
> 逐模块的实测数字（含「哪些模块有类无测试」这张表）见 [`测试与覆盖率矩阵.md`](测试与覆盖率矩阵.md)。

## 集成测试为什么默认不跑

- 6 个 `*IT` 依赖 Testcontainers + Docker（MySQL / Redis 真容器），`mvn test` 阶段**不执行**，只有 `mvn verify` 才跑；
- 因此本地全量汇总「180 个测试 / 174 通过 / 0 失败 / 6 跳过」里的 6 个跳过是**集成测试**，
  不是漏测、也不是失败被吞掉；
- 这 6 个由 `.github/workflows/integration-test.yml` 在 CI 里跑（Actions 额度恢复后），
  或者本地 `mvn verify`（需要 Docker Desktop 在跑）；
- 纯领域 / 应用层测试不启 Spring 上下文，所以 `mvn test` 在无 Docker、无外网的机器上也能全绿；
  这是刻意的设计（见 ADR-001 的可测试性驱动特征），不是「测试没覆盖到才跑得快」。
