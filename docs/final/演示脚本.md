# 演示脚本

现场演示用。每一步写了**操作**、**该看到什么**、**失败时怎么办**。

原则：**能提前起的服务提前起好，能截图的提前截好。** 现场只演示一定会成功的部分，不确定的东西用截图兜底。

---

## 零、演示前 30 分钟

### 启动全栈

```bash
cd deploy
docker compose up -d --build
docker compose ps
```

**预期**：6 个容器 `Up`（mysql、redis、backend、web、prometheus、grafana）。

**如果没有 Docker**，改用本地方式：

```bash
# 终端 1：中间件
docker compose -f deploy/docker-compose.yml up -d mysql redis

# 终端 2：后端（注意是 dev,demo 两个 profile）
cd backend
mvn spring-boot:run -pl co-bootstrap -Dspring-boot.run.profiles=dev,demo

# 终端 3：前端
cd frontend && npm install && npm run dev
```

**兜底**：全启动失败就只讲 PPT + 截图，别在台上跟环境较劲超过 2 分钟。

## 一、演示主线：一条完整的业务链路

> 全程 5 分钟。讲一句话做一个动作，不要边点边解释每个按钮。

### 1. 登录（20 秒）

- **操作**：右上角登录，账号 `2023001`，密码 `Campus2026`
- **该看到**：头像出现，导航栏显示用户名
- **话术**：「种子账号由 `DemoDataSeeder` 通过应用服务创建，不是 SQL 插的——所以它走的是真实的密码策略和 bcrypt 加密。」

### 2. 提问（40 秒）

- **操作**：点「提问」，标题填「跳表的查找为什么是 O(log n)」，标签加两个，提交
- **该看到**：跳转到问题详情页，列表里出现新问题
- **话术**：「标题限制 10 到 150 字，标签 1 到 5 个并且去重。这些不是前端校验，是领域层的规则——绕过前端直接调接口也会被拒。」

### 3. 换账号回答（60 秒）

- **操作**：登出，用 `2023002` 登录，找到刚才的问题，写一条回答
- **该看到**：回答出现在列表里
- **话术**：「注意这里换账号了。同一个人既能提问又能回答，但不能给自己的内容投票。」

### 4. 投票（30 秒）

- **操作**：用 `2023002` 给 `2023001` 的问题投 +1
- **该看到**：票数变化
- **话术**：「每人每内容一票。再点一次是撤销，投反对票是改投——不是累加。」

### 5. 采纳（60 秒）——**全场重点**

- **操作**：换回 `2023001`，点回答的「采纳」
- **该看到**：回答标记为已采纳，问题状态变化
- **话术**：
  > 「现在注意看。提问者只做了一个动作——点采纳。但后台发生了六件事：写发件箱、异步投递、声誉 +15、徽章判定、悬赏结算、通知投影。
  >
  > 为什么要这么绕？因为采纳是问答上下文的事，声誉是另一个上下文的事。直接调用就把两个上下文焊死了。」

### 6. 验证声誉与通知（60 秒）

- **操作**：切到 `2023002` 的声誉页面；再看通知
- **该看到**：声誉增加 15 分，有一条「你的回答被采纳」的通知
- **话术**：
  > 「这 15 分不是直接加在字段上的，是账本里多了一条流水。账户余额是流水的汇总结果——所以任何一笔都能追溯到来源。」

### 7. 搜索（30 秒）

- **操作**：搜索框输入「跳表」
- **该看到**：命中刚才的问题
- **话术**：「中文分词。搜『跳表』能命中『跳表的查找为什么是 O(log n)』，不是字符串匹配。」

## 二、工程侧演示（3 分钟）

### 8. CI 现场（60 秒）

- **操作**：打开 GitHub Actions，点开 `develop` 最新一次 run
- **讲什么**：
  - 六条流水线分别管什么
  - **三道必需检查**：`skeleton-check`、`frontend-check`、`SonarQube 质量门禁`
  - 分支保护：管理员也不能绕过

**话术**：「这些不是摆设。我们自己合并 PR 时就被拦过——检查没过就是合不进去。」

### 9. 覆盖率门禁（60 秒）

- **操作**：打开「后端构建与验证」步骤日志，搜 `All coverage checks have been met`
- **讲什么**：
  > 「关键不在这个数字，在它写在哪。阈值写在根 POM，父 POM 的 plugins 被 27 个模块全部继承。以前是 CI 里的一个 `-D` 参数，只守一个模块，换个模块就漏。现在换不掉——要绕过必须改 POM 留痕。」

### 10. 架构约束（30 秒）

- **操作**：打开 `ArchitectureTest` 的代码，指一下规则
- **话术**：「domain 层不能依赖 infrastructure。这条规则如果被违反，CI 直接红。架构不是画在 PPT 上的，是构建的一部分。」

## 三、兜底方案

| 故障 | 处理 |
| --- | --- |
| 全栈起不来 | 直接用本地 `dev,demo` 方式，只演示前端和接口 |
| 前端也起不来 | 用 `docs/05-质量/smoke/qa-flow.http` 在 IDE 里跑，响应就是证据 |
| 网络断了 | 所有 CI 截图提前存本地，别依赖现场联网 |
| 某个操作报错 | 不要现场排查。说「这一步我提前验证过，现在环境有问题」，跳到下一步 |
| 时间不够 | 砍掉第 8、9、10 三段工程演示，用一句「CI 状态截图在 PPT 第 8 页」带过 |

---

## 四、不要做的事

- **不要现场改代码**。出问题就跳过，改代码只会让情况更糟。
- **不要说「这个本来应该……」**。要么演示成功，要么直接承认这一步环境有问题。
- **不要在台上解释报错信息**。台下看不懂，台上浪费时间。
- **不要念 PPT**。讲稿在脑子里，PPT 只是给听众的视觉锚点。
