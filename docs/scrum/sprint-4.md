## 回顾

**Keep**

- 集成测试当成硬门守，宁可红着不合，这次骨架一补完立刻转绿，说明门禁是真在拦东西。
- 合并前后都回读快照，HEAD 和 Issue 状态对得上。
- 覆盖率口径统一到根 POM 的 `check-all-modules` 之后，本地 `mvn verify` 与 CI 跑同一套规则，不再有 `-D` 绕过的空间（见 `docs/reports/覆盖率说明.md`）。
- 收口材料逐条追到 PR / commit sha，而不是只看 Issue 的关闭状态。

**Drop**

- 拿 token 拼进 git 远程 URL 推送，被 Windows 凭据管理器存成一个假账号，后面要避免。
- 覆盖率一直报单模块口径，容易被误读成全后端达标。
- 建 Issue 时复制模板不核对，导致「输出物」字段与标题错位（见 `docs/04-计划/S4-收口任务书.md` 开头）。
- 把跳过分支的 success 当部署成功；绿灯必须逐 job、逐 step 核对（#101 的教训）。

**Start**

- 发布前先确认「门禁在 main 上也能过」，不是只在 PR 上过。
- 建 Issue 后 5 分钟内自检：标题、输出物、验收标准三者是否对得上；发现缺陷立即开 Issue 打标签，修复 PR 用 `Closes` 关联。
- 每个收口项留可复核证据（PR / commit sha / 命令输出 / 截图 / 录屏），没有证据的项如实留白，不代签、不虚构会议与访谈。
