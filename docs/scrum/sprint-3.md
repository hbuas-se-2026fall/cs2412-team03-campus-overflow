### 本 Sprint 发现并处置的缺陷

**前后端契约错位**

决议：前端另取教师权限字段，后端 `QuestionQueryService` / `PermissionsView.canManage` 不动。挂在 #18 交 @moOvO760。

## 回顾

**Keep**

- 先批准、再轮询、后合并。`blocked` 多是缺批准，不是落后。
- Issue 闭环以主干代码为准。#10、#12 是核对 `Question.java` / `Vote.java` / `Comment.java` 与测试后才关的。
- PR 正文写清「做了什么 / 证据 / 未验收项」，评审成本明显更低。

**Drop**

- PR 正文写 `Closes #x` 却不核对是否真关，#10、#12 因此一直挂着。
- 合并脚本在 `PUT` 失败时仍关 Issue，#37–#40 曾误关一次，已回退。
- 把团队自加严的 DoD 当成课程硬门槛，Docker 真机验证不是老师明文指标，不该卡住主干。

**Start**

- 串行合并，一次只合一个 PR，合完立刻通知其余作者 Update branch。
- 未验收项一律另开 Issue 追踪，不在 PR 里写「已完成」。
- 每次合并后回读一次快照：HEAD + Issue 状态。
