## 回顾

**Keep**

- 故事地图和 Backlog 同一天出，拆 Task 时不用反复回来问「这条属于哪个故事」。
- 先定 22SP 再拆 Task，容量有上限，避免了「什么都承诺」。

**Drop**

- 计划文档写「待填」的地方太多，`Sprint0-计划.md` 至今有多处【待填】。
- Gherkin 验收标准写在 Issue 里，但没有同步成 `.feature` 文件，两者对不上。

**Start**

- 每个 Sprint 的交付物写明具体路径，不含糊到「提交截图」这种程度。

> **口径说明（2026-11-13，见 #107）**：`docs/01-团队/会议纪要/` 目录没有 Sprint1 Planning 纪要。`docs/04-计划/Sprint1-计划.md` 把时间盒写成「建议 2026-11-03 至 2026-11-09（起止以 Planning 站会确认为准）」，仓库里没有该站会的记录；#28 要求的「故事拆 Task 并分配到人」是通过该计划文档与 Issue 异步完成的。因此如实记一句：**Sprint1 Planning 未单独召开，任务拆解通过 Issue / 计划文档异步完成**，会议纪要目录不放这个文件，避免「说开过、却找不到纪要」。
